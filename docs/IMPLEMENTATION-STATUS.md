# Implementation status — 2026-10-02, P5 implementation complete

## Completed packages

- P0: ArcMandate public repository, pinned Node/Foundry dependencies, ignored secrets, network configuration and RPC preflight. Initial commit `25f7575`.
- P1: Shared TypeScript/Solidity START, FREEZE and WITHDRAW digest fixtures; strict SLH-DSA-SHA2-128s precompile wrapper; browser Worker signing and Arc testnet verifier probe. Commit `e91ffa6`.
- P2: One-session Arc USDC vault with owner/PQ hybrid START and withdrawal, agent payment controls, both freeze paths, state counters, replay protection, events and rollback tests. Contract source was deployed from commit `e23da59` with solc 0.8.28, Paris EVM and optimizer 200.
- P3: Versioned encrypted PQ keyfile (`scrypt` N=131072/r=8/p=1, 32-byte salt, AES-256-GCM with 12-byte IV and authenticated metadata), strict 16 KiB/profile/field validation, Worker generate/export/import/structured sign/local verify/lock, and a browser recovery test harness. Secret bytes stay inside the Worker; import proves the restored key by signing a random challenge.
- P4: English single-page EIP-1193 wallet UI: wallet/network checks, vault opening and deployment, restored-key funding gate, policy review, hybrid sessions, both freeze paths, hybrid withdrawal, receipt links and wallet-free read-only view. ABI/bytecode are generated from the pinned Foundry artifact. Mainnet reads are available; management is testnet-only until release gates. P4 extends the pushed P3 baseline `a6da1f7`; see Git history for the package commit.
- P5: Testnet-only agent payment CLI (`npm run agent:pay`) with a local per-request journal. It saves a random 32-byte `paymentId`, session and payment intent before signing, then the exact signed transaction and hash before broadcast. Restart checks receipt and `usedPaymentIds`; it searches `AgentPaid` events if the ID was consumed but a receipt is unavailable. An unresolved transaction is rebroadcast with the same signed bytes/nonce, never a fresh payment ID. The P2 demo now uses this journal for its two actual agent payments and writes a version-2 manifest with explicit `mined_success` and `simulation_rejection` evidence types.

## Limits and decisions

- Disposable P2 testnet keys remain in a local unencrypted, ignored file for that script only; the P3 encrypted product keyfile is separate.
- The demo skips steps already saved in its manifest after an interrupted run. Its agent payment journal survives process restart; the management-step crash window above remains. The P5 proof is for its deployed testnet contract and disposable accounts. The public manifest has `sourceCommit: working-tree` because the implementation was uncommitted during the run.
- The agent CLI intentionally rebroadcasts the original signed transaction and does not automatically replace it with a higher-fee transaction. A persistently dropped/underpriced transaction needs manual review of the journal, nonce and onchain state before any replacement; a new `paymentId` must not be created for that request.
- Arc RPC latest-head responses lagged a mined receipt briefly. Revert simulations are therefore pinned to the preceding receipt's block to prove the intended state. See `docs/DECISIONS.md`.
- This is a prototype testnet deployment, not a mainnet release or audit. Mainnet funding and publication are later P6/P7 work.
- The eventual mainnet demo needs an owner wallet funded for deployment, vault funding of 1 USDC, and small gas balances for the agent and PQ freeze relay. P6 will calculate the live cost from testnet gas evidence and current fees before asking for any mainnet funding.
